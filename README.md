# 🔬 GastricSentinel

> **Multimodal AI for gastric cancer classification** — fusing histopathology, genomics, and clinical data into a single explainable prediction.

---

## 🧬 What is GastricSentinel?

**GastricSentinel** is a full-stack multimodal AI web application for gastric cancer classification. It fuses three data modalities — histopathological images, genomic profiles, and clinical records — through a fusion layer, with explainability via **Grad-CAM** (image heatmaps) and **SHAP** (genomic/clinical feature importance).

Gastric cancer is one of the leading causes of cancer-related deaths worldwide. Early and accurate classification is critical, yet manual histopathological screening is slow, labor-intensive, and prone to human error. GastricSentinel aims to assist pathologists and researchers with a fast, multimodal, and explainable second opinion.

## 📊 Current Results

| Model | Task | Data | Result |
|---|---|---|---|
| Image classifier (`train.py`) | Abnormal / Normal tissue | GasHisSDB | 98.9% test accuracy, 0.988 macro-F1 |
| Genomic + clinical (`train_genomic_clinical.py`) | 5-class molecular subtype (CIN/EBV/GS/MSI/POLE) | TCGA-STAD, 383 patients | 86% accuracy, 0.68 macro-F1 |
| Late-fusion packaging (`train_fusion_model.py`) | Runs both branches, evaluates image model | GasHisSDB + TCGA-STAD | 93.2% image accuracy, 0.99 ROC-AUC |

All three modalities use real, domain-matched data — GasHisSDB for images, real TCGA-STAD genomic and clinical records. No synthetic data remains in the pipeline.

> Genomic subtype classification is weakest on STAD_POLE and STAD_GS — both are rare classes in TCGA-STAD (POLE-mutant gastric cancer is ~1–2% of cases), so this reflects real data scarcity rather than a model bug.

**Citation:** *"The results shown here are in whole or in part based upon data generated by the TCGA Research Network: https://www.cancer.gov/tcga."*

## ✨ Features

- 🖼️ **Histopathological Image Analysis** — CNN classifier trained on real gastric tissue via GasHisSDB
- 🧬 **Genomic & Clinical Data Integration** — TCGA-STAD genomic and clinical records
- 🔀 **Fusion Layer** — combines image, genomic, and clinical embeddings before classification *(joint per-patient fusion still in progress — see To Do)*
- 🔥 **Grad-CAM Visualizations** — gradient-weighted heatmaps highlighting influential tissue regions
- 📊 **SHAP Explainability** — feature importance across genomic and clinical inputs
- 📄 **Downloadable PDF Report** — predictions, risk score, and Grad-CAM visualizations
- 🤖 **Integrated Chatbot** — conversational assistant to guide users through the platform
- 🗄️ **Supabase** — Postgres-backed backend-as-a-service for auth, real-time API, and storage
- 🌐 **Full-Stack Web App** — responsive frontend with a Python REST API backend
- 📁 **Modular Architecture** — separated `frontend`, `backend`, and `training` modules

## 🚀 Getting Started

### Prerequisites
- Python 3.9+
- Node.js (if using a bundler for frontend)
- pip

### 1. Clone the Repository
```
git clone https://github.com/adyashaexe/GastricSentinel.git
cd GastricSentinel
```

### 2. Set Up the Backend
```
cd backend
pip install -r requirements.txt
python app.py
```
The backend API will start at `http://localhost:5000` (or as configured).

### 3. Launch the Frontend
```
cd frontend
python -m http.server 3000
```
Then visit `http://localhost:3000`.

### 4. Train the Models
```
cd training
python train.py                      # image classifier
python train_genomic_clinical.py     # genomic + clinical classifier
python train_fusion_model.py         # evaluate both branches together
```

### 5. Run Inference on a Single Image
```
python training/predict.py --image path/to/tissue_image.png
```

```
Histopathology Images  ──►  CNN Encoder  ──────────────────┐
                                                            │
Genomic Profiles       ──►  Genomic Encoder  ──────────►  Fusion Layer  ──►  Classification Output
                                                            │
Clinical Records       ──►  Clinical Encoder  ────────────┘
```

### Explainability

| Method | Modality | What it shows |
|---|---|---|
| **Grad-CAM** | Image | Heatmap overlay highlighting the tissue regions most influential to the prediction |
| **SHAP** | Genomic & Clinical | Feature importance scores showing which genes and clinical variables drive the model's decision |

## ✅ To Do

- [ ] **Real joint fusion** — `train_fusion_model.py` currently runs the image and genomic/clinical models independently on unrelated samples; it doesn't yet combine them into one per-patient prediction. Needs a shared patient/sample key and an actual fusion step (weighted ensemble or a small meta-classifier over both models' outputs).
- [ ] **Link image data to real patients** — GasHisSDB tiles aren't linked to TCGA-STAD patient IDs. If true multimodal fusion is the goal, need matched histopathology slides for the same patients as the genomic/clinical records (e.g. TCGA-STAD's own diagnostic slide images via GDC).
- [ ] **Improve STAD_GS / STAD_POLE performance** — both underperform due to low sample counts (10 and 1 in the test set respectively); consider class weighting, oversampling, or grouping rare subtypes.
- [ ] **SHAP integration** for the genomic/clinical model — not yet wired up to real predictions.
- [ ] **Grad-CAM integration** in the backend/frontend pipeline — implemented at the model level, not yet exposed through the app.
- [ ] **Backend endpoints** for genomic/clinical and fusion inference — `backend/` currently only serves the image model.
- [ ] **PDF report generation** — not yet implemented.
- [ ] **Patient/slide-level split audit** — confirm the GasHisSDB train/val/test split is not leaking near-duplicate patches across splits (same caution that caught the earlier CRC-VAL-HE-7K issue).
